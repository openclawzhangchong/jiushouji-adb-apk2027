# 开发任务书 · 设备 Kiosk 应用

- **文档性质**：可直接下发给程序员的开发任务书
- **目标设备**：`XXB` / `b906`（MediaTek MT6582，Android 5.1 / API 21）
- **依据**：全部结论来自真机实测，证据见 [`06-Kiosk可行性实测.md`](06-Kiosk可行性实测.md)
- **参考实现**：[`../tools/kiosk-test/`](../tools/kiosk-test/)（已跑通的基线代码，可直接改）

---

## 一、任务目标

开发一个 Android 应用，安装到目标设备后满足：

1. **开机自动启动**，无需人工干预
2. **接管整个屏幕**，用户无法退出到系统桌面
3. **长期稳定运行**，崩溃/异常后能自动恢复
4. **不依赖网络也能启动**（网络仅用于业务功能）

**交付物**：一个签名后的 `.apk` + 一键部署脚本。

## 二、硬约束清单（对照打勾）

> 这些不是"建议"，是设备物理限制。违反任何一条都会导致装不上或崩溃。

### 编译配置

- [ ] `minSdkVersion = 21`（**必须 ≤ 21**）
- [ ] `targetSdkVersion = 22`（锁在 21~22，规避后续 API 行为变更）
- [ ] 若有 native 代码：`ndk { abiFilters 'armeabi-v7a' }` —— **设备只支持 `armeabi-v7a`，无 arm64/x86**
- [ ] 解压 APK 检查 `lib/` 下**没有** `arm64-v8a` 或 `x86` 目录
- [ ] 依赖里**没有** `com.google.android.gms:*` / `com.google.firebase:*` —— **设备无任何 Google 服务，必崩**

### 技术选型

- [ ] **界面用原生 View，不用 WebView**
      （理由：设备 WebView 是 **Chrome 37 / 2014 年**，ES6 语法全不可用，见 §三）
- [ ] 若必须用 WebView：JS 必须 Babel 编译到 **ES5** + `core-js` polyfill；
      禁用 `fetch`、CSS Grid、CSS 变量、`position:sticky`

### 功能适配

- [ ] 所有 `getDefaultSensor()` 结果都判了 `null`
      （设备**声明有指南针但实际没有磁力计**，`hasSystemFeature` 不可信）
- [ ] 摄像头按 `Camera.getNumberOfCameras()` 遍历，**按单摄设计**
      （设备声明有前置摄像头，实际只有 1 个）
- [ ] 锁竖屏：`android:screenOrientation="portrait"` + `configChanges="orientation|screenSize|keyboardHidden"`
- [ ] 界面按 **411 × 731 dp** 验证不溢出（720×1280 @ 280dpi）
- [ ] 中文输入不依赖系统输入法（**设备无中文输入法**）

### 性能

- [ ] 主线程零 IO / 零网络 / 零大计算
- [ ] **启动路径按单核预算**（冷启动阶段只有 1 核 @598 MHz，负载上来才 4 核全开）
- [ ] 图片用 `inSampleSize` 压缩，不加载超过屏幕分辨率的图
- [ ] 开启 R8 / ProGuard
- [ ] 冷启动实测 < 3 秒
- [ ] **慎用持续全屏动画**（WebView 复杂渲染 + 高频重绘的组合负载可能触发框架软重启，
      但常规界面 43–56 FPS 可达，不必过度保守）

## 三、为什么必须避开 WebView（给程序员的依据）

真机跑了 52 项特性检测，结果 **20/52 通过**，WebView 版本是 **Chrome 37.0.0.0**：

| 类别 | 不可用 |
|---|---|
| **ES6 语法** | `let/const`、箭头函数、模板字符串、`class`、默认参数、解构、展开运算符、`generator`、`async/await`、`for...of` —— **10 项全灭** |
| 标准库 | `Map`/`Set`、`Object.assign`、`Array.from/includes`、`String.includes`、`Promise.finally`、`Symbol`、`Proxy` |
| Web API | `fetch()`、`URLSearchParams`、`TextEncoder`、`IntersectionObserver` |
| CSS | **Grid**、**CSS 变量 `var()`**、`position:sticky` |

**可用**：Promise、WebSocket、localStorage、canvas 2d + **webgl**、flexbox、TLS 1.2。

> 完整表格见 [`04-WebView兼容性实测.md`](04-WebView兼容性实测.md)。
> **一句话**：用 WebView 就要额外维护一整套 ES5 降级链，而且性能更差。**原生 View 是更省事的选择。**

## 四、必须实现的功能

### 4.1 三件套声明（缺一不可）

```xml
<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<uses-permission android:name="android.permission.WAKE_LOCK" />
<uses-permission android:name="android.permission.DISABLE_KEYGUARD" />

<application android:label="你的应用名">

    <!-- ① 主界面：同时是 LAUNCHER 和 HOME -->
    <activity
        android:name=".MainActivity"
        android:exported="true"
        android:launchMode="singleTask"
        android:stateNotNeeded="true"
        android:screenOrientation="portrait"
        android:configChanges="orientation|screenSize|keyboardHidden">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
            <category android:name="android.intent.category.HOME" />
            <category android:name="android.intent.category.DEFAULT" />
        </intent-filter>
    </activity>

    <!-- ② 开机自启 + 崩溃自恢复 -->
    <receiver android:name=".BootReceiver" android:enabled="true" android:exported="true">
        <intent-filter android:priority="1000">
            <action android:name="android.intent.action.BOOT_COMPLETED" />
            <action android:name="android.intent.action.QUICKBOOT_POWERON" />
        </intent-filter>
    </receiver>

    <!-- ③ 设备管理员：Device Owner / LockTask 的前提 -->
    <receiver
        android:name=".AdminReceiver"
        android:permission="android.permission.BIND_DEVICE_ADMIN"
        android:exported="true">
        <meta-data android:name="android.app.device_admin"
                   android:resource="@xml/device_admin" />
        <intent-filter>
            <action android:name="android.app.action.DEVICE_ADMIN_ENABLED" />
        </intent-filter>
    </receiver>

</application>
```

### 4.2 开机自启（`BootReceiver`）

```java
public class BootReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {
        Intent i = new Intent(context, MainActivity.class);
        i.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK | Intent.FLAG_ACTIVITY_CLEAR_TOP);
        try {
            context.startActivity(i);
        } catch (Throwable ignored) { }
    }
}
```

> ⚠️ **`BOOT_COMPLETED` 不只是"开机"用，还是免费的崩溃自恢复机制。**
> 实测：framework 软重启后会**重新广播** `BOOT_COMPLETED`，应用会被自动拉起。
> **即使应用已经是默认桌面，也务必保留这个接收器。**

### 4.3 屏幕常亮 + 解除锁屏

```java
@Override
protected void onCreate(Bundle b) {
    super.onCreate(b);
    getWindow().addFlags(
            WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON
          | WindowManager.LayoutParams.FLAG_SHOW_WHEN_LOCKED
          | WindowManager.LayoutParams.FLAG_DISMISS_KEYGUARD
          | WindowManager.LayoutParams.FLAG_TURN_SCREEN_ON);
    // ...
}
```

> ⚠️ 实测 `settings put secure lockscreen.disabled 1` **无效**，`setKeyguardDisabled()` 是 API 23+。
> **5.1 上只能用上面这组 Window flag。**

### 4.4 零人工接管桌面 + 锁定（Device Owner 路径）

设为 Device Owner 后，在应用内一次性完成以下动作，**无需人工点任何按钮**：

```java
DevicePolicyManager dpm = (DevicePolicyManager)
        getSystemService(Context.DEVICE_POLICY_SERVICE);
ComponentName admin = new ComponentName(this, AdminReceiver.class);

// ① 允许自己进入锁定任务
dpm.setLockTaskPackages(admin, new String[]{ getPackageName() });

// ② 把自己钉成默认桌面（免去人工点"始终"）
IntentFilter filter = new IntentFilter(Intent.ACTION_MAIN);
filter.addCategory(Intent.CATEGORY_HOME);
filter.addCategory(Intent.CATEGORY_DEFAULT);
ComponentName home = new ComponentName(this, MainActivity.class);
dpm.addPersistentPreferredActivity(admin, filter, home);

// ③ 进入锁定模式（Home / Back / Recent 全被接管）
startLockTask();
```

**降级方案**（拿不到 Device Owner 时）：只声明 HOME，
装完后**必须人工在设备上点一次「始终」**——因为 `pm disable-user` 不可用，
没法自动干掉原桌面（实测见 [`06-Kiosk可行性实测.md`](06-Kiosk可行性实测.md) §4.2）。

### 4.5 保活与自恢复

```java
// 前台 Service，被杀后自动重启（Android 5.1 后台限制宽松，START_STICKY 有效）
@Override
public int onStartCommand(Intent intent, int flags, int startId) {
    return START_STICKY;
}
```

配合 `AlarmManager.setRepeating()` 定期自检，在被强停后重新拉起。

## 五、构建配置模板

```gradle
android {
    compileSdk 34

    defaultConfig {
        applicationId "com.yourcompany.kiosk"
        minSdk 21                    // ★
        targetSdk 22                 // ★
        versionCode 1
        versionName "1.0"
        ndk { abiFilters 'armeabi-v7a' }   // ★ 有 native 代码时
    }

    compileOptions {
        sourceCompatibility JavaVersion.VERSION_1_8
        targetCompatibility JavaVersion.VERSION_1_8
    }

    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
        }
    }
}
```

**依赖选择**：遇到 `uses-sdk:minSdkVersion 21 cannot be smaller than version N` 报错时，
**把该库降级到最后一个支持 minSdk 21 的版本**，不要提高 minSdk。

## 六、部署流程（已实测验证）

```bash
PKG=com.yourcompany.kiosk
APK=app-release.apk

# 1. 安装
adb install -r $APK

# 2. ★ 首次启动 —— 必须！否则应用处于 stopped 状态，收不到开机广播
adb shell am start -n $PKG/.MainActivity

# 3. 设为 Device Owner（要求设备【无已登录账号】，全新设备才行）
adb shell dpm set-device-owner $PKG/.AdminReceiver

# 4. 重启验证
adb reboot
```

**第 3 步之后，应用内的 4.4 节代码会自动完成桌面接管与锁定，无需人工。**

### ⚠️ 部署注意

| 事项 | 说明 |
|---|---|
| **第 2 步不能省** | 实测装完 `stopped=true notLaunched=true`，此时收不到 `BOOT_COMPLETED` |
| Device Owner 不可逆 | 只能恢复出厂设置清除；实测 `pm uninstall` 报 `DELETE_FAILED_DEVICE_POLICY_MANAGER` |
| 恢复出厂会清 ADB 授权 | 之后 `adb devices` 变 `unauthorized`，需人工在设备上点一次「允许」 |
| 必须在无账号时设置 | 设备一旦登录任何账号，`dpm set-device-owner` 就设不了了 |

## 七、验收标准（可逐条在设备上验证）

交付时请附上以下每条的实测截图或日志：

| # | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| 1 | 能装上 | `adb install -r app.apk` | 输出 `Success` |
| 2 | ABI 正确 | `adb shell "logcat -d \| grep abi="` | 含 `abi=armeabi-v7a` |

| 5 | **开机自启** | `adb reboot`，等 60 秒 | 界面自动出现，无需任何操作 |
| 6 | **无法退出** | 按 Home / Back / Recent | 始终停留在应用界面 |
| 7 | 常亮 | 静置 5 分钟 | 屏幕不熄灭 |
| 8 | 锁屏不挡 | 关屏再开屏 | 直接进应用界面，不出现锁屏 |
| 9 | 崩溃自恢复 | `adb shell am force-stop <pkg>` | 30 秒内自动重新拉起 |
| 10 | 断电恢复 | 拔电等 10 秒再上电 | 界面自动出现 |
| 11 | 冷启动耗时 | `adb shell am start -W -n <pkg>/.MainActivity` | `TotalTime` < 3000 ms |
| 12 | 界面不溢出 | 截图检查 | 411×731 dp 内无裁切 |

### 一键自检脚本

```bash
#!/bin/bash
PKG=com.yourcompany.kiosk
ADB=adb

echo "=== 1. 安装检查 ==="
$ADB shell "pm list packages | grep $PKG" || { echo "未安装"; exit 1; }

echo "=== 2. 组件注册检查 ==="
$ADB shell "dumpsys package $PKG" | grep -E "BOOT_COMPLETED|DEVICE_ADMIN_ENABLED|category.HOME" \
  || echo "⚠️ 组件声明缺失"

echo "=== 3. Device Owner ==="
$ADB shell "dumpsys device_policy" | grep -A2 "Enabled Device Admins"

echo "=== 4. 重启测试 ==="
echo "重启中..."; $ADB shell reboot
$ADB wait-for-device
for i in $(seq 1 20); do
  sleep 3
  BC=$($ADB shell getprop sys.boot_completed 2>/dev/null | tr -d '\r\n ')
  [ "$BC" = "1" ] && break
done
sleep 15
echo "当前前台: $($ADB shell 'dumpsys window | grep mCurrentFocus')"

echo "=== 5. 锁定测试（手动按 Home 后重跑本行）==="
echo "按 Home 键后，焦点应仍为 $PKG"

echo "=== 6. 冷启动耗时 ==="
$ADB shell "am force-stop $PKG"
$ADB shell "am start -W -n $PKG/.MainActivity" | grep TotalTime
```

## 八、已知风险与规避

| 风险 | 现象 | 规避 |
|---|---|---|
| **框架软重启** | 系统服务突然全无，约 30 秒恢复 | 避免持续动画 / 高频重绘；保留 `BOOT_COMPLETED` 自动恢复 |
| **WebView 老** | H5 白屏 / 语法报错 | 用原生 View；若必须用 WebView 则 ES5 + polyfill |
| **冷启动单核** | 首屏卡顿几秒 | 重活延后到后台线程，先出界面 |
| **内存 1.93 GB** | 大图易 OOM | 图片压缩，避免 `largeHeap` |
| **无中文输入法** | 中文输不进去 | 自带软键盘或允许英文 |
| **序列号不唯一** | 多台设备 ID 冲突 | 首启生成 UUID 存本地 |
| **无 TLS 1.3** | 连不上只开 TLS1.3 的服务端 | 服务端保留 TLS 1.2 |
