# 连接与部署环境

> 电脑侧（Windows）需要准备什么，以及连不上时怎么排查。
> 本机实测环境：Windows 10.0.19045 / Git Bash + PowerShell。

---

## 一、安装 adb

### 方式 A：winget（推荐，本机采用）

```powershell
winget install --id Google.PlatformTools --accept-package-agreements --accept-source-agreements --disable-interactivity
```

装完版本：**Android SDK Platform-Tools 37.0.1**（adb 1.0.41）。

安装位置：

```
%LOCALAPPDATA%\Microsoft\WinGet\Packages\Google.PlatformTools_Microsoft.Winget.Source_8wekyb3d8bbwe\platform-tools\adb.exe
```

`%LOCALAPPDATA%\Microsoft\WinGet\Links\` 下会生成 `adb.exe` / `fastboot.exe` 软链，
**但当前已打开的终端读不到新 PATH**，需要新开终端或用完整路径调用。

### 方式 B：官方压缩包（免安装）

下载 <https://dl.google.com/android/repository/platform-tools-latest-windows.zip>
解压到任意目录，直接用完整路径调用 `adb.exe`。

## 二、驱动

**本项目不需要装任何 Android USB 驱动。**

现代 adb（platform-tools 24+）不依赖 Google/OEM 专用驱动，
只要设备的 ADB 接口被系统 **WinUSB** 驱动加载即可。

本机实测该接口状态：

```
Service        = WINUSB
CompatibleIds  = USB\Class_ff&SubClass_42&Prot_01    ← ADB 接口签名
Status         = OK
```

## 三、首次连接流程

```powershell
$adb = "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\Google.PlatformTools_Microsoft.Winget.Source_8wekyb3d8bbwe\platform-tools\adb.exe"

& $adb kill-server
& $adb start-server
& $adb devices -l
```

预期输出：

```
List of devices attached
0123456789ABCDEF       device product:full_b906 model:XXB device:b906 transport_id:1
```

> `kill-server` 在 daemon 未启动时会报
> `cannot connect to daemon at tcp:5037` —— **这是正常的，不是错误**。

### 如果显示 `unauthorized`

**看设备屏幕**，点「允许 USB 调试」（勾「一律允许」）。
旧设备上这个弹窗可能藏在通知栏里。

始终点不动 → 设备上执行：开发者选项 →「撤销 USB 调试授权」→ 拔插重来。

## 四、排错：分三层定位

「连不上」有五种完全不同的原因，**不要一上来就重装驱动**。按层排查：

### 第 1 层：USB 枚举层（Windows 认不认）

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -like 'USB\*' } |
  Select-Object Status,Class,FriendlyName,InstanceId | Format-Table -AutoSize | Out-String -Width 200

# 缺驱动的设备会出现在这里
Get-PnpDevice -PresentOnly | Where-Object { $_.Status -ne 'OK' } |
  Select-Object Status,Class,FriendlyName,InstanceId | Format-Table -AutoSize
```

### 第 2 层：ADB 接口层（设备有没有把调试口暴露出来）

对可疑的 VID/PID 读描述符：

```powershell
foreach ($p in @('DEVPKEY_Device_HardwareIds','DEVPKEY_Device_CompatibleIds',
                 'DEVPKEY_Device_Service','DEVPKEY_Device_BusReportedDeviceDesc')) {
  (Get-PnpDeviceProperty -InstanceId '<InstanceId>' -KeyName $p).Data
}
```

判读：

| 看到什么 | 说明 | 怎么办 |
|---|---|---|
| 只有 `USB\MS_COMP_MTP` / `Class_ff&SubClass_ff` | 设备只给了 MTP，**ADB 口没开** | 设备上确认 USB 调试已开，USB 模式选「传输文件/MTP」，拔插重试 |
| `USB\Class_ff&SubClass_42&Prot_01` | **ADB 口正常** | 继续下一层 |
| `Status = Error` 且无 Class | 缺驱动 | 才需要装 Google USB Driver |

> MTK 公版机常把 MI_00 / MI_01 的 `BusReportedDeviceDesc` **都写成 "MTP"**，
> **别信这个名字，只信 `CompatibleIds`**。

### 第 3 层：授权层

`adb devices` 输出 `unauthorized` → 设备端点授权。
输出 `offline` → `adb kill-server` + 拔插。

### 速查表

| 现象 | 层 | 处理 |
|---|---|---|
| PnP 里根本没有该 VID/PID | USB 枚举 | 换线/换口，设备选 MTP 模式 |
| 只有 MTP 接口，无 FF/42/01 | ADB 接口 | 设备上确认 USB 调试已开 + 重新拔插 |
| 有 FF/42/01，但 Status=Error | 驱动 | 装 Google USB Driver |
| `adb devices` 空但接口正常 | 客户端 | 装 platform-tools |
| `unauthorized` | 授权 | 设备端点「允许」 |
| `offline` | 连接 | `adb kill-server` + 拔插 |

## 五、环境坑（Windows 特有）

| 坑 | 说明 |
|---|---|
| 新装 adb 后当前终端找不到 | PATH 是启动时读取的，**新开终端**或用完整路径 |
| 别从 Bash 里调 PowerShell | 本机安全策略会直接拒绝，PowerShell 要走 PowerShell 工具 |
| `& $adb ... 2>&1` 出现红色 `NativeCommandError` | adb 把正常信息（如 `1 file pulled`）写到 stderr，**是噪音不是失败**，看 stdout 的真实结果 |
| 中文输出乱码 | adb 输出与 PowerShell 编码（GBK/UTF-8）混排会乱码。**只信任 ASCII 字段**（型号、版本号、getprop 值）；中文描述用截图确认 |

## 六、设备端命令可用性（影响脚本写法）

**Android 5.1 实测**：

| 有 | 无 |
|---|---|
| `am` `pm` `settings` `input` `screencap` `screenrecord` `dumpsys` `logcat` `monkey` `dpm` `getevent` `sendevent` `setprop` `ps` `top` `ip` `ifconfig` `ping` `netstat` `cp` `mv` `rm` `ls` `date` `reboot` `grep` | `cmd`（6.0+ 才有） `su` `head` `nproc` `tar` `curl` `wget` `toybox` `busybox` |

**写脚本前先探一遍**：

```bash
adb shell "command -v <命令>"
```

### shell 语法坑

Android 的 `sh` 是 mksh/toolbox，**不支持 `(a || b)` 括号分组**：

```bash
# ❌ 报 syntax error: 'always-on' unexpected
adb shell "cat f 2>/dev/null || echo (always-on)"

# ✅ 用 if 或分开两条命令
```

## 七、其他注意事项

- **`ro.serialno = 0123456789ABCDEF` 是 MTK 默认占位值，不唯一**，不能当设备唯一标识
- **`ls /sbin/su` 返回 `Permission denied`** 说的是目录不可读，**不能据此判断有无 root**，
  要看 `ro.secure` / `ro.debuggable`
- **`/proc/loadavg` 在这台设备上读数异常**（连续采样值不变），不要用它判断负载
- **判定真实核心数**读 sysfs，不要数 `cpuinfo`：

  ```bash
  adb shell cat /sys/devices/system/cpu/present   # 硬件有几个，如 0-3
  adb shell cat /sys/devices/system/cpu/online    # 实际在线的，如 0
  ```
