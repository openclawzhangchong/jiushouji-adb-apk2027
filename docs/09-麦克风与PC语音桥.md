## 一句话结论

**这台平板可以做 Windows 的麦克风，而且已经做成了。**
采麦、外放、熄屏保活、断线自恢复全部真机验过；Windows 侧靠一个 VB-Cable 虚拟声卡拿到录音端点。

## 1. 采麦实测

| 项 | 实测值 |
|---|---|
| 特性声明 | `android.hardware.microphone` ✅ |
| 可用配置 | `AudioRecord(VOICE_COMMUNICATION, 16000, CHANNEL_IN_MONO, ENCODING_PCM_16BIT)` |
| `getMinBufferSize(16000, MONO, PCM16)` | **1280**（单位是**字节** = 640 样本 = **40ms**），别当样本数用 |
| 实际申请缓冲 | `min * 4 = 5120` 字节（≈160ms），够吸收抖动 |
| 分包节奏 | 20ms = 320 样本 = **1280 字节/包** |
| 满速上行 | **31603 – 32640 B/s**（理论 32000 B/s = 16000×2），实测 **欠采 0** |
| 静置底噪 | 约 **-48 dBFS** RMS（房间本底，不是电气噪声） |
| 对着外放说话/播语音 | **-8.7 dBFS** 平均、峰值 **-3.3 dBFS**（近距离、外放拉满） |
| 硬件完好性 | 用户 2026-10-30 用录音机手动录过 ✅；本轮又被声学自测二次确认 |

和上游生产代码一致：`xiaole-ptt-android5-2027/src/com/zcstudy/xiaole/ptt/Audio.java:15-40`
用的就是同一套参数，本仓库只是把它抄过来，**没有新的采麦风险**。

⚠️ `VOICE_COMMUNICATION` 在 MTK 上会挂平台回声处理。要做"干净原始音"的对照，
切 `VOICE_RECOGNITION`（本项目的 App 界面上留了一键切换），但**没做过正式 A/B**。

## 2. 熄屏保活：一个 PARTIAL_WAKE_LOCK 就够

**Android 5.1 没有 Doze（6.0 才引入）**，所以不用 Foreground Service、不用通知栏、不用白名单。

```
adb shell dumpsys power | grep "Wake Locks"
  PARTIAL_WAKE_LOCK  'micbridge:up' (uid=10058, pid=…)      ← 持有中
adb shell input keyevent 26                                  # 熄屏
  mWakefulness=Asleep / Display Power: state=OFF
（保持熄灭 75 秒）→ 心跳 14 条全部满速，欠采 0，无断档
```

⚠️ 只验了 **75 秒**，**30 分钟以上的长跑没跑过**。别当成"可以长期挂机"。

## 3. 外放（自测要靠它）

| 事实 | 说明 |
|---|---|
| 扬声器可用 | `android.hardware.audio.output` ✅，`AudioTrack(STREAM_MUSIC, …, MODE_STREAM)` 实测有声 |
| 用 adb 拉满媒体音量 | `adb shell input keyevent 24`（VOLUME_UP）连发十几次即可；`setStereoVolume(1f,1f)` 是**相对**音量，硬件音量还得单独拉 |
| 素材还在盘上 | `/sdcard/Music/` 里留着 `loop1.wav.off`、`loop2.wav.off`(≈10.9s/24kHz)、`loop3.wav`(32.7s)。`.off` 只是当年改名停用，**内容有效可直接播** |

### ★ 声学自测的正确姿势（换了机器也照这个做）

**必须让平板自己外放、再用它自己的麦克风听回来。**
不要用电脑放声音去喂平板麦克风——本项目的开发主机接的显示器（MG2461VI）**没有扬声器**，
电脑外放是静音的，只会得到"全零/只有底噪"的**假失败**。

现成一条命令（在实现仓库里）：

```bash
bash run_selftest.sh /sdcard/Music/loop2.wav.off 34
# 判据：心跳速率≈32000B/s 且欠采0 / 外放段峰值≥-4dBFS / ASR 逐字复现原文
```

本仓库 `xiaole-ptt-android5-2027/test_ptt.sh` 用的是同一方法论（外放已知中文→听回来→对 STT），
只是方向相反（那边是平板外放平板听，这边是平板外放→电脑录→电脑 ASR）。

## 4. 这台设备做"USB 音频上行"时的 adb 四个坑

| # | 坑 | 正解 |
|---|---|---|
| 1 | **`adb reverse --list` 在 Android 5.1 上不可用**，返回 `error: protocol fault (couldn't read status length)` | 但 `adb reverse tcp:X tcp:X` 和 `--remove-all` **正常**。所以隧道存活不能用 list 判，只能"设备在位 + 当前无客户端"就幂等重下发 |
| 2 | **`am start --ez NAME 1` 会被解析成 `false`** | `--ez` 只接受 `true`/`false`。表现为"App 起来了但什么都没发生"，极易误判成代码 bug |
| 3 | `adb devices` 显示 **`offline`** ≠ "等你点授权" | `unauthorized` 才是等点击。`offline` 时授权框**根本不会弹**；本例设备日期是正确的（`date` = 2026-10-30 10:08 CST），所以**不是** RTC 没电那一类老问题，最后靠撤销/重开 USB 调试恢复 |
| 4 | 换一台电脑就要重新点「允许 USB 调试」 | 授权密钥在 `~/.android/adbkey`；删掉重生成会让**平板上的旧授权全部失效**，需要重新点。Git Bash 里传**远程**路径要 `MSYS_NO_PATHCONV=1`（此时本地路径得写成 `E:/...` Windows 形式） |

USB 复合设备在只开 MTP 时是 `USB\VID_0E8D&PID_201D` 的两个接口（`MI_00` WPD + `MI_01` MTP）；
USB 调试开启后 adb 才可见。`adb install` 在这台上走的是 **Push Install** 老流程，正常。

## 5. 与 PC 侧的接口约定（改任何一边都要同步）

```
平板 App  ->  TCP  127.0.0.1:5005  （经 adb reverse tcp:5005 tcp:5005 落到电脑）
载荷      ->  裸 PCM，无包头：16000Hz / 单声道 / 16bit 小端 / 20ms(1280B) 分包
控制      ->  无（断开即停；App 侧 1s→2s→4s→8s 退避重连）
```

选 USB 不选 WiFi 的原因：**平板与主机不在同一网段**（主机有线 192.168.168.x，
本仓库 `README.md` 记录过平板在 192.168.191.x），且一根线顺便供电（`USB powered: true`）。
