### 平台线索（推断）

基带项目串：

```

```

其中 **`LOKYEE82` ≈ `joya82`**，`WET_KK` 的 `KK` 指 KitKat。
公开 ROM 库中可检索到同平台固件：

```
MT6582__alps__K0708__4.4.2__K0708_V1.1.0_190802__KOT49H__joya82_wet_kk.zip
```

**推断**：本机与那批 `K0708` 平板同属 **`joya82` 硬件平台**。
ODM 沿用了该平台设计，把系统从 4.4 升到 5.1，
但**基带仍是 KitKat 时代的老固件**（所以串里还写着 `KK`）。
这是这类公版方案非常典型的做法。

**ODM 厂商已确定**：

```
ro.mediatek.project.path    = device/keytak/b906
ro.mediatek.version.release = ALPS.L0.MP2.V1_KEYTAK6582.WT.L
```

**`KEYTAK`** 就是这套固件的 ODM 厂商代号（`KEYTAK6582` = KEYTAK 家的 MT6582 方案）。
`ALPS.L0.MP2.V1` 是 MTK 的 ALPS 基线版本号。这比基带串的推断更硬——
它是**编译期写死的项目路径**，可以直接拿去检索同厂商的其他固件。

**进一步推断**：这是一台**白色/贴牌平板**，非主流品牌行货。
所有厂商定制包的安装时间戳集中在 `2023-06-19 15:30 ~ 15:50` 这 20 分钟内，

### ✅ 两个「异常」读数已查清（结论：都不是故障）

**1. 「4 核只开 1 核」—— 正常，是省电策略**

跑负载复测，**复现两次**：

| 状态 | `online` | 当前频率 |
|---|---|---|
| 空闲 | `0`（**1 核**） | 598 MHz |
| 施加 8 个忙循环 4 秒后 | `0-3`（**4 核全开**） | 1300 MHz |
| 施加负载 10 秒后 | `0-3`（4 核） | 1300 MHz |
| 释放负载 4 秒后 | `0-2`（**正在逐步关核**） | 598 MHz |

hotplug governor 配置：`is_cpu_hotplug_disable = 0`、`cpu_num_limit = 4`、
`cpu_up_threshold = 90`、`cpu_rush_boost_num = 4`、`cpu_input_boost_num = 2`。

**结论：hotplug 工作完全正常。** 空闲关到 1 核是 MTK 的标准省电行为，
既不是故障，也不是 ODM 的额外限制。
**性能可以按 4 核 @1.3 GHz 预期**，只有冷启动阶段（尚未达到升核阈值）是单核。

原始证据：[`../raw/cpu-hotplug-test-result.txt`](../raw/cpu-hotplug-test-result.txt)、
[`../raw/cpu-hotplug-governor-config.txt`](../raw/cpu-hotplug-governor-config.txt)

**2. `/proc/loadavg` 恒为 ~7 —— 不是坏的，是基线被内核线程垫高**

早期连续采样值几乎不变（7.11 / 7.13 / 7.17 / 7.19），一度被误判为「内核计数异常」。
实际查清：系统里有 **7 个长期处于 `D`（不可中断睡眠）状态的内核线程**：

```
pmic_thread_kth    bat_thread_kthr    hang_detect
wdtk-0   wdtk-1   wdtk-2   wdtk-3
```

它们是 MTK 平台的标准内核线程（看门狗 / 死机检测 / 电源管理 / 电池），
D 状态本身正常，但会被计入 loadavg，把基线永久抬高到 ≈7。

- ❌ 不能直接读绝对值判断应用负载（7.13 就是空闲值）
- ✅ 可以做**增量对比**：施加负载后确实从 7.13 涨到 8.34
- ✅ 要精确看 CPU 利用率，用 `top` 或 `/proc/stat` 两次采样求差

原始证据：[`../raw/dstate-threads.txt`](../raw/dstate-threads.txt)

## 五、能力边界

### ✅ 不需要 root 就能做

- **装应用**：`adb install`（限 API 21 + `armeabi-v7a`）
- **启动 / 强停应用**：`am start` / `am force-stop`
- **模拟输入**：`input tap / swipe / text / keyevent` → 可做自动化
- **改系统设置**：`settings put`
- **截图 / 录屏**：`screencap` / `screenrecord`
- **文件互传**：`adb push / pull`
- **看日志**：`logcat`
- **拉起 MTK 工程模式**：`am start` 调 `com.mediatek.engineermode`
- **设为 Device Owner**：`dpm set-device-owner` ✅ **实测权限检查通过**（shell 有 `MANAGE_DEVICE_ADMINS`）
- **改安全设置**：`settings put secure …` ✅ shell 有 `WRITE_SECURE_SETTINGS`
- **设为默认桌面**：声明 `HOME` category（但**无法自动固定**，见下）

### ❌ 无 root 做不了

- **禁用任何组件 / 包**：`pm disable-user` ❌ **实测被拒绝**
  （`SecurityException: Permission Denial: attempt to change component state … uid=2000`）
  —— shell 没有被授予 `CHANGE_COMPONENT_ENABLED_STATE`。
  报错在包特定逻辑之前触发，所以**对任何包都不成立**。
  → **后果：无法自动禁用原桌面 Launcher3**，批量部署时要人工点一次「始终」，
  除非走 Device Owner。shell 被授予的 66 条权限清单见
  [`../raw/shell-permissions.txt`](../raw/shell-permissions.txt)
- 修改 `/system`、真正删除预装应用
- 读取其他应用的私有数据（`/data/data/*`）
- 改 `build.prop`、禁用系统组件
- 完整系统备份
- 开无线 ADB（5.1 不支持，且需 root 改 `persist.adb.tcp.port`）

### ⚠️ 现实限制

- **WebView 37**：现代网页基本打不开
- **无中文输入法**
- **Android 5.1 无安全更新**：**不要登录敏感账号**
- **冷启动阶段只有 1 核**（负载上来后才 4 核全开）
